# Dispatcher Config Reference

> Loaded by the stackisle skill when the user wants to edit dispatcher config:
> vhosts, farms, cache rules, rewrites, or allowed/denied URLs.
> The user runs every command (see CLAUDE.md, Working agreement).

## Config location

`INSTALL_DIR/dispatcher/src/` (default `sdk/dispatcher/src/`), seeded by
`make dispatcher` from `SDK_DIR/dispatcher-sdk-X.Y.Z/src/`. It's mounted at
`/mnt/dev/src` in `aem-dispatcher` and applied at container start by Adobe's
`import_sdk_config.sh` hook (mounted by `docker-compose.yml`, mirroring `bin/docker_run.sh`).

> `sdk/` is gitignored, so changes here aren't version-controlled. For real
> projects, keep the dispatcher config in the AEM project repo (open decision,
> see `docs/session-handoff.md`).

The seeded config uses **flexible mode**: `opt-in/USE_SOURCES_DIRECTLY` is present,
so the validator runs `validator full -relaxed`.

```
src/
├── conf.d/
│   ├── available_vhosts/default.vhost        # IMMUTABLE — ServerAlias "*"
│   ├── enabled_vhosts/                       # symlinks to active vhosts
│   ├── rewrites/rewrite.rules                # editable — included by the vhost
│   └── variables/custom.vars                 # editable — your Define variables
├── conf.dispatcher.d/
│   ├── available_farms/default.farm          # IMMUTABLE — /publishfarm
│   ├── enabled_farms/                        # symlinks to active farms
│   ├── virtualhosts/virtualhosts.any         # editable — includes default_virtualhosts.any ("*")
│   ├── filters/filters.any                   # editable — allow/deny rules
│   ├── cache/rules.any                       # editable — what gets cached
│   ├── clientheaders/clientheaders.any       # editable — headers passed to Publish
│   └── renders/default_renders.any           # IMMUTABLE — ${AEM_HOST}:${AEM_PORT}
└── opt-in/USE_SOURCES_DIRECTLY
```

**Immutable files** say *"DO NOT EDIT this file, your changes will have no impact
on your deployment"*. AEMaaCS ignores changes to them, and phase 3 of
`make dispatcher-validate` fails. The source of truth for the list is
`/etc/httpd/immutable.files.txt` inside the dispatcher image:
```bash
docker run --rm --entrypoint cat adobe/aem-cs/dispatcher-publish:<ver> /etc/httpd/immutable.files.txt
```

## Current state: defaults accept every host

| Layer | Setting | Effect |
|---|---|---|
| `default.vhost` | `ServerAlias "*"` | Apache vhost matches any `Host` header |
| `default_virtualhosts.any` (via `virtualhosts.any`) | `"*"` | `/publishfarm` handles any host |

So `http://localhost:9999/…` and every `https://<CUSTOM_DOMAIN>/…` (nginx passes
`Host: <domain>`) reach Publish. Both add the response header `X-Vhost: publish`:
```bash
curl -sI -H "Host: dev-local-www-brand.com" http://localhost:9999/content/wknd/us/en.html | grep -i x-vhost
```

## Per-domain config ("step 10b", the AEMaaCS-supported way)

**Farm hosts:** edit `conf.dispatcher.d/virtualhosts/virtualhosts.any`. It's
meant to be edited. Keep `localhost` for port 9999:
```
"dev-local-www-brand.com"
"dev-local-www-shop.brand.com"
"dev-local-www-b2b.brand.com"
"dev-local-www-new.brand.com"
"localhost"
```

**Vhost per site:** copy `default.vhost` to `available_vhosts/brand.vhost`, set
`ServerName` / `ServerAlias` to the site's domains and adjust its rewrites. Then
enable it:
```bash
cd sdk/dispatcher/src/conf.d/enabled_vhosts
ln -s ../available_vhosts/brand.vhost brand.vhost
```
Keep `default.vhost` enabled as the catch-all, or replace it (the comment in
`default.vhost` describes removing its link). Apache picks the first vhost
whose name/alias matches.

Afterwards: `make dispatcher-validate`, then `make stop-dispatcher start-dispatcher`.

## Common tasks

### Allow a URL (filters)
Edit `conf.dispatcher.d/filters/filters.any`. The last matching rule wins:
```
/0100 { /type "allow" /method "GET" /url "/api/v1/*" }
```

### Cache a path
Edit `conf.dispatcher.d/cache/rules.any`:
```
/0100 { /type "allow" /glob "/api/v1/public/*" }
```

### Rewrite rule
Edit `conf.d/rewrites/rewrite.rules` (already included by the vhost):
```apache
RewriteRule ^/home$ /content/my-site/en/home.html [L,R=301]
```

### Ignore marketing query parameters (validator warning `ignoreUrlParameters`)
`default.farm` is immutable, so enable it in a copied farm, following the
commented example there (`$include "../cache/marketing_query_parameters.any"`).

## Environment (set by docker-compose.yml, as docker_run.sh does)

| Variable | Value |
|---|---|
| `AEM_HOST` / `AEM_PORT` | `host.docker.internal` / `AEM_PUBLISH_PORT` (4503) |
| `ENVIRONMENT_TYPE` | `dev` |
| `DISP_LOG_LEVEL` / `REWRITE_LOG_LEVEL` | from `.env`, lowercase: `trace1` `debug` `info` `warn` `error` |
| `HOST_OS` | `uname` of the host |
| `ENABLE_MANAGED_REWRITE_MAPS_FLAG` | `true` |
| `DOCROOT` (inside the image) | cache docroot; cache persisted in volume `aem-dispatcher-cache` |

## Validate

```bash
make dispatcher-validate
```
- Phase 1: validator rules
- Phase 2: `httpd -t` in the dispatcher image (**uses Docker**)
- Phase 3: immutability check

Always use the make target. Adobe's `validate.sh` mounts `${PWD}/cache`, and
the target runs it from `sdk/dispatcher` so no root-owned `cache/` lands in the
project root.

## Hot reload (optional, for iterating on config)

Adobe's `bin/docker_run_hot_reload.sh` runs a second dispatcher that reloads on
file changes (flexible mode required, and it's on). It also mounts
`${PWD}/cache`, so run it from `sdk/dispatcher`, on a free port:
```bash
cd sdk/dispatcher
../dispatcher-sdk-*/bin/docker_run_hot_reload.sh "$PWD/src" host.docker.internal:4503 8080
```
**Not yet tested in this project.** On Linux, `host.docker.internal` may not
resolve inside a container started by Adobe's script (our compose file adds it
via `extra_hosts`). If so, use the Docker bridge IP instead, e.g. `172.17.0.1:4503`.
